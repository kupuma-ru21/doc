# スキル名
テーブル設計

## やること
1. 既存コードを読み込む

2. 読み込んだ仕様書をもとに、以下を必ず質問する
  - 重複データが作成できてしまうケースがある場合はDBに制約を加えるか質問する(例: 前提: 本の作成機能で章を作る必要がある。質問: 章の重複を許容するか否か。 許容しない場合DBにUnique制約を加えるか?)

3. テーブル設計に関する疑問点を洗い出し、疑問点がなくなるまで質問し続ける
  - 疑問点はAskUserQuestionツールを使って質問する
  - 質問に対する回答の選択肢は最大4つまでにする
  - 質問は1つずつ行う

4. テーブル設計書を作成する
  - テーブル設計書は以下の内容を含む
    - テーブル名
    - カラム名
    - カラムの型
    - カラムの制約(例: NotNull, Unique etc)
  - テーブル設計書の中で整合性が取れないケースが発生するかセルフレビューする(最低10回)
    - 整合性の部分で私に疑問がある場合は以下に従う
      - 疑問点はAskUserQuestionツールを使って質問する
      - 質問に対する回答の選択肢は最大4つまでにする
      - 質問は1つずつ行う
  - 作業しているディレクトリ内に「テーブル設計書」を保存する
    - 「テーブル設計書」を保存する適切なディレクトリを探す
    - 適切な該当ディレクトリが存在する場合、該当ディレクトリに保存する
    - 適切なディレクトリが見つからない場合、どこに作成するか私に質問する
      - 質問と同時にどこに作成するのがおすすめか提示する

5. テーブル作成
  - ORM(Gqlgen, Prisma etc)が使われてる場合、自動生成コードを実行する
  - プロジェクトの設定ファイル(例: MakeFile etc)を確認して静的チェックを行い、エラーが0になるまで修正し続ける
