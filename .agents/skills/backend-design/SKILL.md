# スキル名
バックエンド設計

## やること
1. 実装に関わる画面を全て確認して、どの画面で使うAPIから実装するかAskUserQuestionツールを使って質問する

2. 1で選択した画面で使うAPIの中で、どのAPIから実装するかAskUserQuestionツールを使って質問する

3. 既存コードを読み込む

4. 2で選択したAPIについて疑問点がなくなるまでAskUserQuestionツールを使って最低10回質問する
- 質問に対する回答の選択肢は最大4つまでにする
- 質問は1つずつ行う
- 画像アップロードの処理が必要な画面がある場合は、許容される画像のフォーマット、サイズ、枚数を質問する
- 作成予定のAPIでuser_idが必要な場合、inputにuser_idを含めるべきか質問する
  - バックエンド側でuser_idを(ログインの認証情報から)取得できる場合は含めない
  - バックエンド側でuser_idを取得できない場合は含める

5. バックエンド設計書を以下のフォーマットで作成する

```
## バックエンド実装計画書

- 画面A
  - API名 (未実装)
    - APIが提供する機能の説明
    - 詳細説明(例: Aという条件ではAPI XXXは実行されない etc)
```

  - 2で回答したAPIだけをスコープとする
  - バックエンド設計書の中で整合性が取れないケースが発生するかセルフレビューする(最低10回)
    - 整合性の部分で私に疑問がある場合は以下に従う
      - 疑問点はAskUserQuestionツールを使って質問する
      - 質問に対する回答の選択肢は最大4つまでにする
      - 質問は1つずつ行う
  - 作業しているディレクトリ内にバックエンド設計書を保存する
    - 「バックエンド設計書」を保存する適切なディレクトリを探す
      - 適切なディレクトリが存在する場合、該当ディレクトリに「backend-design/[画面名(英語)]」ディレクトリを作成
      - 「backend-design/[画面名(英語)]」ディレクトリにバックエンド設計書を保存する、ファイル名は「 [API名(英語)].md」
    - 適切なディレクトリが見つからない場合、どこに作成するか私に質問する
      - 質問と同時にどこに作成するのがおすすめか提示する
      - 「backend-design/[画面名(英語)]」ディレクトリを作成する
      - 「backend-design/[画面名(英語)]」ディレクトリにバックエンド設計書を保存する、ファイル名は「 [API名(英語)].md」

5. バックエンド実装
  - バックエンド設計書のディレクトリの入力を必須とする、バックエンド設計書のディレクトリの入力がない場合は決して実装コードを書かない
  - バックエンド設計書をもとに作成予定のAPIのテストを実装する
  - 該当APIを実装する
  - 実装完了後、以下を確認
    - テストコードがpassことを確認する
    - プロジェクトの設定ファイル(例: MakeFile etc)を確認してformat, 静的チェックを行い、エラーが0になるまで修正し続ける
    - 以下のようにバックエンド実装計画書に実装済みの機能をマークする

```
## バックエンド実装計画書

- 画面A
  - API名 (実装済)
    - APIが提供する機能の説明
    - 詳細説明(例: Aという条件ではAPI XXXは実行されない etc)
```
