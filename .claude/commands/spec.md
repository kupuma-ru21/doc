# /spec コマンド

`$ARGUMENTS`（= 作りたいものを説明した文章）を受け取り、そこから仕様書 Markdown を生成します。

## 手順

### 1. 入力文章の受け取り
- `$ARGUMENTS` に文章が入っている場合はそれを使う。
- 空の場合は、AskUserQuestion で「何を作りたいか」の説明文を求める。文章が得られるまで次に進まない。

### 2. 保存先の推測と確認
- プロジェクト内のディレクトリ構成を調査し、仕様書の置き場所を推測する。
  ```bash
  # 既存の仕様書・ドキュメント置き場を探す
  find . -type d \( -name docs -o -name spec -o -name specs -o -name doc \) -not -path '*/node_modules/*' 2>/dev/null | head -20
  ```
- 調査結果から保存先ディレクトリの候補を提示し、AskUserQuestion で確認する（推奨候補に「(推奨)」を表示）。
- 候補が見つからない場合も、推測した既定パス（例: `docs/specs`）を推奨として提示する。

### 3. 仕様書ファイルの作成
- 確認した保存先に、タイムスタンプ付きディレクトリを作って `spec.md` を作成する。
  ```bash
  DIR={確認した保存先ディレクトリ}
  NAME={文章から付けた要約スラッグ（英小文字・ハイフン区切り）}
  TIMESTAMP=$(date +%Y%m%d%H%M%S)
  mkdir -p "${DIR}/${TIMESTAMP}_${NAME}"
  echo "${DIR}/${TIMESTAMP}_${NAME}/spec.md"
  ```
- 上記パスの `spec.md` に、文章と確認内容をもとに以下の構成で仕様書を書き込む（該当しない節は省略可）。

  ```markdown
  # {タイトル}

  ## 概要
  {1〜2文で何を作るか}

  ## 背景・目的
  {なぜ作るのか}

  ## スコープ
  - 対象とすること
  - 対象外とすること

  ## 機能要件
  - {要件1}
  - {要件2}

  ## 非機能要件
  - {性能・セキュリティ・運用などの要件}

  ## 制約・前提
  - {技術的制約や前提条件}

  ## 未確定事項
  - {残課題があれば}
  ```

- 作成後、`echo "✅ {パス} を作成しました"` で完了を伝え、生成した仕様書の内容を要約して提示する。

### 4. タスク設計へ続ける
- 仕様書の作成が終わったら `@~/.claude/skills/task-design/SKILL.md` を読み込んで実行する。

## 使い方
```
/spec ユーザー認証機能を作りたい。メールとパスワードでログインできるようにする
  → 不明点を確認 → 保存先を確認 → spec.md を生成 → task-design 開始
```
