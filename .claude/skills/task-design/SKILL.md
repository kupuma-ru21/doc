# スキル名
タスク設計

## 前提
- ユーザーに対しての質問は、AskUserQuestionツールを使って質問する
  - 質問に対する回答の選択肢は最大4つまでにする
  - 質問は1つずつ行う

- やることの2で作成するファイルはmarkdown形式のTODOリスト(checkbox付き)の形式で作成する

## やること
1. 仕様理解フェーズ
  - `@~/.claude/commands/spec.md`で作成された仕様書を読み込む

2. 読み込んだ仕様を確認、以下を順番に行う
  - テーブル設計
    - `@~/.claude/skills/table-design/SKILL.md` を読み込んで実行する
    - 回答をもとに、`@~/.claude/commands/spec.md`で作成された仕様書と同階層にtable-design.mdを作成する
  - バックエンド設計
    - `@~/.claude/skills/backend-design/SKILL.md` を読み込んで実行する
    - 回答をもとに、`@~/.claude/commands/spec.md`で作成された仕様書と同階層にbackend-design.mdを作成する
  - フロントエンド設計
    - `@~/.claude/skills/frontend-design/SKILL.md` を読み込んで実行する
    - 回答をもとに、`@~/.claude/commands/spec.md`で作成された仕様書と同階層にfrontend-design.mdを作成する

3. 各設計書に対し整合性が取れないケースが発生するか最低10回セルフレビューする

4. 実装(自律実行)
  - 原則ユーザーに承認・確認を求めず、TODOリストが全て完了するまで自律的に実装を進める
  - TODOごとに以下のサイクルを **1つずつ** 繰り返す(複数TODOをまとめて実装しない)
    1. 実装サブエージェントを起動し、対象TODOを実装させる
       - 対象TODOの内容と、関連する各設計書(table-design.md / backend-design.md / frontend-design.md)の該当箇所をサブエージェントに渡す
    2. レビュー用サブエージェントを起動し、実装内容を独立してレビューさせる
       - レビュー担当は実装の差分(`git diff`)を一次情報として、設計書との整合性・テストの有無・リグレッションを確認する
    3. レビューが承認(APPROVED)なら、TODOリストの該当TODOにチェックを入れて次のTODOへ進む
       - レビューが却下(REJECTED)なら、指摘内容を添えて実装サブエージェントに再実装させる(最大2回まで。それでも解決しなければ前提を置いて記録し、次のTODOへ)
  - 実装に関する疑問点が発生した場合は、原則 **ユーザーに質問せず** 合理的な前提を置いて実装を続行し、置いた前提をTODOリストに明記する
    - ただし仕様の根本矛盾など、前提を置いても続行不能な場合に限り、`## 前提`に従って質問する


5. 実装完了後、以下を確認
  - プロジェクトの設定ファイル(例: MakeFile, package.json etc)を確認して静的チェックを行い、エラーが0になるまで修正し続ける
  - 仕様書に記載されている内容が全て実装されていることを確認する
