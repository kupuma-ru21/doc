# スキル名
フロントエンド設計

## やること
1. 機能について疑問点がなくなるまでAskUserQuestionツールを使って最低10回質問する
  - 質問に対する回答の選択肢は最大4つまでにする
  - 質問は1つずつ行う
  - 画像アップロードの処理が必要な画面がある場合は、許容される画像のフォーマット、サイズ、枚数を質問する
  - モバイル対応するか否かを質問する
  - フォーム実装が必要な場合、フォーム管理はすでに使われてるライブラリ(例： react-hook-form)を使うか否かを私に質問する
  - ページ内で固定した方が良さそうなUIを確認する。確認した後はどの要素を固定するか私に質問する
      質問形式はSTEP 2-0と同じ
  - CSR or SSRのどっちで実装するか私に質問する
  - テーブルで一覧を表示する場合、ページ自体をスクロールするか、テーブル内だけでスクロールするか質問する

4. フロントエンド設計書を以下のフォーマットで作成する

```
## フロントエンド実装計画書

- 画面A
  - 機能a (未実装)
```

  - 2で回答した機能だけをスコープとする
  - フロントエンド設計書の中で整合性が取れないケースが発生するかセルフレビューする(最低10回)
    - 整合性の部分で私に疑問がある場合は以下に従う
      - 疑問点はAskUserQuestionツールを使って質問する
      - 質問に対する回答の選択肢は最大4つまでにする
      - 質問は1つずつ行う
  - 作業しているディレクトリ内にフロントエンド設計書を保存する
    - 「フロントエンド設計書」を保存する適切なディレクトリを探す
      - 適切なディレクトリが存在する場合、該当ディレクトリに「frontend-design/[画面名(英語)]」ディレクトリを作成
      - 「frontend-design/[画面名(英語)]」ディレクトリにフロントエンド設計書を保存する、ファイル名は「[機能名(英語)].md」
    - 適切なディレクトリが見つからない場合、どこに作成するか私に質問する
      - 質問と同時にどこに作成するのがおすすめか提示する
      - 「frontend-design/[画面名(英語)]」ディレクトリを作成する
      - 「frontend-design/[画面名(英語)]」ディレクトリにフロントエンド設計書を保存する、ファイル名は「[機能名(英語)].md」

5. フロントエンド実装
  - フロントエンド設計書のディレクトリの入力を必須とする、フロントエンド設計書のディレクトリの入力がない場合は決して実装コードを書かない
  - フロントエンド設計書をもとに作成予定の機能に対するテストを実装する
  - 該当の機能を実装する
  - 実装完了後、以下を確認
    - ローディングハンドリングが漏れている場合、ローディングの実装を追加する
    - エラーハンドリングが漏れている場合、エラーハンドリングの実装を追加する
        - APIのエラーメッセージをそのまま表示するようにする。Fallback込みで実装する
    - テストコードがpassことを確認する
    - プロジェクトの設定ファイル(例: package.json etc)を確認してformat, 静的チェックを行い、エラーが0になるまで修正し続ける
    - 実装完了後、以下のようにフロントエンド実装計画書に実装済みの機能をマークする

```
## フロントエンド実装計画書

- 画面A
  - 機能a (実装済)
```
